# Синтетические снимки бедра с известной ротацией из КТ (план, 23.09.2026)

## Зачем

Голова «ротация бедра» — F1 0,583 при 36 положительных. Четыре подхода на наших 150 снимках
не помогли (сеть точек, ансамбль CNN, окно у малого вертела). Внешних снимков DXA бедра
с меткой ротации в открытом доступе нет (поиск 23.09: Mendeley, Kaggle, GitHub, статьи —
данные только «по запросу»). Выход из ловушки малой выборки — **синтез**.

DXA-изображение по сути — проекция костной ткани (мягкие ткани вычитаются двумя
энергиями). Из КТ с маской бедренной кости можно получить похожую проекцию и, главное,
**повернуть кость на точно известный угол**. Ротация при DXA — это поворот бедра вокруг
оси диафиза, её признак — видимость малого вертела.

## Данные

`~/extra-data/totalsegmentator_full/Totalsegmentator_dataset_v201.zip` на Aldan:
1228 КТ, у каждой `ct.nii.gz` и `segmentations/femur_left.nii.gz`, `femur_right.nii.gz`,
`hip_left.nii.gz`, `hip_right.nii.gz`, `sacrum.nii.gz`, `vertebrae_*.nii.gz`;
`meta.csv` (тип исследования, производитель). Брать исследования, где маска бедра не пустая
и захватывает проксимальный отдел (головка, шейка, оба вертела, ≥ 6 см диафиза).

## Генератор (training/build_drr_hip.py)

1. Для каждой КТ и каждой стороны: вырезать объём вокруг проксимального бедра + вертлужной
   впадины (маски femur_X и hip_X с запасом 2 см).
2. Костная ткань: HU внутри объединения масок femur_X ∪ hip_X, отрицательные значения → 0
   (имитация вычитания мягких тканей).
3. Ось диафиза: главная компонента точек маски бедра ниже малого вертела (нижняя треть маски).
4. Поворот ТОЛЬКО бедренной кости вокруг оси диафиза на угол θ ∈ {−30, −20, −10, 0, +10, +20,
   +30}° (таз не поворачивается — как при укладке). scipy.ndimage.affine_transform, порядок 1.
5. Проекция по передне-задней оси (сумма по оси y объёма в системе пациента) → 2D.
6. Ресэмплинг к 0,6 мм/пикс, зеркалирование левой стороны в «правую» ориентацию как в наших
   снимках (сверить с data/train: где на экране медиальная сторона), кадрирование ~300×265
   с головкой вверху-медиально, нормировка той же `dxaqc.foreign_patch.normalize`.
7. Метка: θ (градусы, регрессия) и сторона. Исходная ротация пациента в КТ неизвестна
   (лёжа стопы обычно наружу на ~10–20°) — это шум метки, для предобучения допустим.
8. Сохранить npz: images, theta, side, ct_id. Для проверки — контактный лист PNG
   синтетических снимков рядом с нашими настоящими, ОБЯЗАТЕЛЬНО посмотреть глазами до обучения.

Объём для первой проверки: 200 КТ × 2 стороны × 7 углов ≈ 2800 изображений.

## Обучение и честная проверка

1. Предобучение: backbone той же CNN, что в сервисе (resnet18 из `train_baselines.py`, b2),
   задача — регрессия θ (или классификация |θ| > 15°). Разбиение по ct_id.
2. Дообучение головы ротации на наших 150 снимках бедра — теми же 5 внешними фолдами
   по исследованиям, порог по объединённым внутренним OOF (`training/train_foreign_nested.py`
   как образец схемы).
3. Сравнение с текущей CNN (F1 0,583 / AUC 0,771) — **на 3 seed**, главная метрика AUC.
   Критерий внедрения: AUC выше на каждом seed и в среднем ≥ +0,02.

## Риски

- Синтетическая проекция КТ отличается от DXA (разрешение, шум, профиль яркости) —
  поэтому только предобучение, вся оценка — на наших снимках.
- Если на контактном листе синтетика не похожа на наши бедра — сначала чинить генератор
  (контраст, ориентация, кадрирование), не обучать.
- Разбиение предобучения строго по КТ, чтобы повороты одного бедра не попали в обе части.
