# Памятка разметчику: запуск и возврат результатов

> Если вам помогает ИИ-ассистент — дайте ему `docs/for_collaborator_ai.md`:
> там объяснено, что проверять в вашей разметке и каким инструментом.

Три задачи, делать в этом порядке: **ось → предметы → бедро**. Порядок важен:
пересмотр «оси» надо делать незамыленным взглядом, до того как насмотришься
на снимки в других задачах.

## Перед началом

```bash
cd ~/projects/dxa-quality-ai
git pull                      # взять свежие исправления, их за сутки было много
```

## 1. Ось (порт 8768)

```bash
.venv/bin/python tools/axis_review.py --reviewer den --part 2 --clean-pixels-confirmed
```

39 снимков плюс скрытые повторы. Инструмент не показывает ни исходную метку,
ни угол, ни прогноз модели — это сделано намеренно, и подсматривать их в таблицах
перед разметкой нельзя, иначе результат обесценится.

Ответы: `1` — ось отклонена, `2` — норма, `0` — не могу решить. После вердикта
появляется список причин (множественный выбор) — заполнять обязательно, **причины
и есть главный результат этой задачи**. Подробности: `docs/annotation_axis_review.md`.

## 2. Посторонние предметы (порт 8766)

```bash
.venv/bin/python tools/foreign_annotator.py --index data/index/images.csv --root . \
    --annotator den --part 2 --scores experiments/results/b2/oof.csv
```

Флаг `--scores` обязателен: он поднимает наверх самые ценные снимки.

Клавиши: `L` — режим линии (для тонких дуг по диагонали, прямоугольник для них
не годится), `H` — рамка-ловушка, `U` — «не уверен», `Enter` — подтвердить, что
предметов нет, `[` и `]` — толщина линии. Подробности: `docs/annotation_foreign.md`.

Два момента, которых нет в инструкции:

- **Примерно на трети снимков с меткой предмет не виден без специального поиска.**
  Это нормально, не считайте, что пропустили очевидное.
- **Если на снимке без метки видно то же самое, что на снимках с меткой** (такая же
  яркая дуга у верхнего края), — не помечайте это ловушкой. Поставьте обычную рамку,
  нажмите `U` и напишите в комментарии. Такие случаи мы разберём отдельно.

## 3. Ключевые точки бедра (порт 8767)

```bash
.venv/bin/python tools/hip_annotator.py --index data/index/images.csv --root . \
    --annotator den --part 2
```

Шесть точек: H (центр головки), B₁ и B₂ (края шейки в самом узком месте),
T (самая медиальная точка малого вертела), D и D₂ (середина кости на направляющих
20 и 50 мм ниже T — линии рисуются сами). Правила с формулировками:
`docs/annotation_hip.md`.

**Если точка не видна — не ставьте её «примерно».** У каждой точки есть состояния
`not_visible`, `out_of_frame`, `uncertain`; для малого вертела невидимость сама по себе
может оказаться полезным признаком, а выдуманная координата только испортит данные.

После первых 15–20 снимков остановитесь и прогоните:

```bash
.venv/bin/python tools/hip_annotator.py --report data/annotations/hip_points_den.json
```

Он покажет, проходят ли скрытые повторы пороги повторяемости (1,5 мм для точек кости,
3 мм для вертела). Если не проходят — лучше уточнить правило сразу, чем разметить всё
с систематическим сдвигом.

## Как сохраняются результаты

**Сохранять вручную не нужно.** Файл пишется после каждого действия, поэтому
прерваться можно в любой момент: закрыть вкладку, выключить компьютер. При следующем
запуске работа продолжится с того же места.

Файлы появятся в `data/annotations/`:

- `axis_review_den_20260920.json`
- `foreign_boxes_den.json`
- `hip_points_den.json`

## Как вернуть результаты

Через git, как обычный код:

```bash
git add data/annotations/
git commit -m "Разметка: <что именно сделано>"
git pull --rebase && git push
```

Папка `data/annotations/` версионируется (идентификаторы исследований, по подтверждению
организатора, случайные и пациентов не обозначают). Снимки и индекс в git по-прежнему
не попадают — они большие и не нужны для обмена.

Коммитить лучше после каждой законченной задачи, а не в самом конце: так работа
не потеряется и её видно второй стороне.

## Если что-то сломалось

- Инструмент «оси» упал и не запускается: рядом с JSON остался файл `*.json.lock` —
  удалите его, убедившись, что прежний процесс завершён.
- Порт занят: добавьте `--port` с другим номером.
- **Работайте в одной вкладке.** Две вкладки на один файл могут мешать друг другу.
- Если инструмент при запуске пишет, что в файле есть записи вне текущей выборки, —
  так и должно быть, они сохраняются нетронутыми. Главное, не запускать с чужим
  `--part` и чужим `--annotator`.
