# Протокол финальной оценки (фиксируется ДО прогона)

Дата фиксации: 20.09.2026. Документ пишется перед финальным прогоном и после него
не редактируется — правки только отдельным разделом «Отклонения от протокола».

Причина: обе внешние рецензии (astra, fable 5.1) назвали главной методической
ошибкой то, что голова-победитель для каждого нарушения выбиралась по тем же
внешним фолдам, по которым считался итог. Поэтому macro-F1 ≈ 0,67 — разведочная
оценка, и в отчёте она называется именно так.

## 1. Решения, зафиксированные до финального расчёта

Важная поправка (astra, 20.09.2026): назвать эти решения «априорными» нельзя.
Априорное — это принятое до просмотра результатов, которыми оно оценивается;
наша маршрутизация выбрана после разведочного этапа на той же выборке. Поэтому
правильная формулировка — **«зафиксировано после разведки, до финального расчёта»**,
и финальное число описывается как повторная вложенная CV-оценка, устраняющая
выбор голов по результатам этого прогона, но не как независимая валидация.
Новое разбиение тех же снимков независимого теста не создаёт.

| нарушение | источник прогноза | обоснование, не зависящее от метрики |
|---|---|---|
| обрезка поясницы (Th12 / гребни) | геометрия по предсказанным точкам | правило дословно повторяет текст ТЗ: «половина Th12 в кадре», «гребни подвздошных костей в кадре» — интерпретируемо и проверяемо врачом |
| ось позвоночника | угол хорды Th12→L5, порог 5° | порог 5° взят из ТЗ, а не подобран |
| ротация бедра | CNN | геометрического правила нет, пока не размечен малый вертел |
| посторонние предметы | CNN | объект не описывается опорными точками скелета |
| область интереса бедра | CNN | то же; 7 положительных — отдельно отмечается как статистически незначимая оценка |

Маршрутизация зашита в `src/dxaqc/service_model.py` и на этапе финального прогона
не меняется ни при каком результате.

## 2. Что считается один раз

- Вложенная групповая кросс-валидация: 5 внешних фолдов по исследованиям,
  4 внутренних. Все гиперпараметры и пороги выбираются ТОЛЬКО во внутреннем цикле.
- Порог каждой CNN-головы — по внутренним фолдам, критерий зафиксирован заранее:
  максимум F1 при специфичности не ниже 0,80, центр плато.
- Итог: macro-F1 по 5 нарушениям + доверительные интервалы кластерным бутстрэпом
  по исследованиям (1000 повторов).

## 3. Как отчитываемся о двух числах

1. Разведочная фаза (что делали и что видели) — 0,67, с явной пометкой
   «оценка смещена вверх: выбор варианта по внешним фолдам».
2. Финальная фаза — одно число по настоящему протоколу.
   Именно оно идёт в презентацию как результат.
3. Если финальное число окажется ниже разведочного — публикуется всё равно, а
   разница обсуждается как величина селекционного смещения. Это сильная часть
   доклада, а не слабая.

## 4. Ограничения, объявляемые заранее

- «Ось»: метка плохо согласуется с проверенными геометрическими определениями
  (угол хорды, угол линии гребней, максимальное и нормированное отклонение,
  кривизна). Лучший F1 этого семейства правил 0,455–0,476, причём порог подбирался
  на тех же данных, то есть и эта величина оптимистична. Это ограничение семейства
  правил, а не доказанный потолок задачи.
- «Область интереса бедра»: 7 положительных, интервал заведомо широкий.
- Размер выборки: ~100 снимков с ручными точками, 499 снимков всего.

## 5. Уточнения по рецензии astra (20.09.2026)

**Порог полезности эксперимента, заданный заранее:** Δmacro-F1 ≥ 0,02, то есть
ΔF1 ≥ 0,10 одной головы при неизменных остальных. Это порог практической пользы,
а не статистической значимости; нижняя граница парного кластерного ДИ выше нуля
на такой выборке достижима редко и требуется только для сильного утверждения.

**Цена одной исправленной ошибки** (чтобы выбирать выгодную ошибку, а не интересную):
ΔF1 при переводе одного FN в TP = 2(TP+1)/(2·TP+FP+FN+1) − F1; вклад в macro-F1 — вдвое-
впятеро меньше (делится на 5 меток).

**Разделение данных соблюдает вся цепочка,** а не только классификатор: сеть точек,
преобразование точек в признаки, классификатор, детектор предметов. Классификатор
поверх предсказанных точек обучается на cross-fitted точках, а не на in-sample —
иначе точки в обучении систематически точнее, чем в проде.

**Сравнения только на одинаковых снимках:** oracle по ручным точкам и геометрия по
предсказанным сравниваются на одном и том же подмножестве, иначе разница AUC частично
отражает состав выборки. В парном бутстрэпе ресемплируются одни и те же исследования.

**Пороги в бутстрэпе не переоптимизируются** — берутся зафиксированные.
Для ресемплов без положительных примеров (актуально для ROI бедра, 7 положительных)
правило обработки задаётся заранее, и доля таких ресемплов публикуется.

**Разный охват разметки не усредняется молча:** у меток разное число размеченных
снимков и разная распространённость; таблица по каждой метке (TP/FP/FN, F1, AP, ДИ,
число исследований с положительными) идёт рядом с macro-F1.

**Отчёт тремя блоками:** (1) основной macro-F1 по всем пяти нарушениям без исключений;
(2) метрики каждой метки; (3) дополнительный macro-F1 по четырём меткам — явно как
анализ чувствительности, а не замена основного результата. Метку «ось» из основной
метрики не исключаем: менять задачу после неудобного результата нельзя.

**Формулировка про «ось» для отчёта:** 0,455–0,476 — лучший F1 *исследованного семейства
угловых правил* на этой выборке, а не установленный потолок задачи. Утверждать
ненадёжность метки можно только после слепого пересмотра положительных И отрицательных
с оценкой согласия и заранее заданной процедурой арбитража. При этом κ и согласие
публикуются как отдельная характеристика разметки, а не как объяснение потолка F1.
