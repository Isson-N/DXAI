# Задание: разметчик ключевых точек бедра `tools/hip_annotator.py`

Ты уже написала нам два инструмента этого семейства: `spine_annotator.py` (точки
позвоночника) и `foreign_annotator.py` (рамки предметов). Нужен третий — точки бедра.
Тот же стек: stdlib `http.server` + `pydicom` + `PIL` + `numpy`, HTML и JS инлайном,
без внешних библиотек, атомарная запись после каждого действия, восстановление сессии,
горячие клавиши, замер времени на снимок.

## ВАЖНО: формат наших данных (трижды спотыкались об это)

В `data/index/images.csv` бинарные метки записаны pandas как **«0.0» / «1.0»**, а не
«0»/«1»; пустая клетка означает «не размечено». Разбирай через `float()`, иначе
инструмент молча не найдёт ни одного снимка. Колонки, которые тебе нужны:
`sop_uid`, `study`, `path` (относительно `--root`), `rows`, `cols`, `region`
(значения `hip` / `spine`), `side` (`L` / `R`), `y_pos` (это и есть метка ротации
на снимках бедра).

## Схема точек — она уже уточнена тобой же и fable, менять не надо

Шесть точек, в этом порядке:

| клавиша | точка | что это |
|---|---|---|
| 1 | **H** | центр головки бедренной кости |
| 2 | **B₁** | верхний край шейки в самом узком её месте |
| 3 | **B₂** | нижний край шейки там же (B₁B₂ дают ширину шейки w) |
| 4 | **T** | наиболее медиально выступающая точка контура малого вертела |
| 5 | **D** | середина между контурами диафиза на 2 см ниже нижнего края малого вертела |
| 6 | **D₂** | то же на 5 см ниже |

Точку N (основание шейки) не размечаем — это середина B₁B₂. Точку G (большой вертел)
выбросили: у неё нет воспроизводимого определения у не-рентгенолога, и её вид зависит
от той самой ротации, которую мы измеряем.

**Отступы 2 см и 5 см** считаются в миллиметрах через масштаб пикселя (0,600 мм по x,
0,606 мм по y) — инструмент должен показывать разметчику горизонтальные направляющие
на этих уровнях, автоматически, от поставленной точки T. Если T не виден — уровни
отсчитываются от середины B₁B₂. Это ключевая деталь: она убирает разброс от «на глаз».

## Состояния точки

У каждой точки, кроме координат, одно из состояний: `visible`, `not_visible`
(есть в кадре, но контур не отличить), `out_of_frame`, `uncertain`.
Для T это критично: при сильной внутренней ротации малый вертел уходит в тень шейки,
и **его невидимость сама по себе может оказаться сильным признаком**. Поэтому:
координату в таком случае не ставить вовсе, а не угадывать.

Дополнительно на каждую точку — уверенность 1–3 (одна клавиша, по умолчанию 3).

## Скрытые повторы (обязательно)

В очередь добавляются **10 повторных показов** уже показанных снимков: каждый ~7-й
снимок из первой половины повторяется в случайном месте второй половины, плюс первые
5 снимков повторяются в конце. Разметчику они ничем не отличаются от новых.
Ключ в файле — `sop_uid#2`, чтобы первый показ не перезаписывался.
Это нужно для проверки повторяемости: пороги приёмки заданы заранее — SD ≤ 1,5 мм для
H, B₁, B₂, D, D₂; ≤ 3 мм для T.

## Отбор снимков

Размечаются только `region == "hip"`. Состав (71 снимок):

1. **Оба снимка всех 23 исследований, где хотя бы один снимок положителен по `y_pos`** —
   это 46 снимков. Из них в 12 исследованиях положительны оба снимка, в 11 — только один.
   Нужны оба, чтобы проверить, не скопирована ли метка с одного бедра на другое.
2. **25 случайных отрицательных** снимков из исследований, где положительных нет.

Порядок перемешан детерминированно (хеш от study+sop_uid, как в прошлых инструментах),
положительные и отрицательные не идут блоками.

## Формат сохранения

`data/annotations/hip_points_<annotator>.json`, схема `dxa-hip-points/1`:

```json
{
  "schema": "dxa-hip-points/1",
  "annotator": "имя",
  "updated": "ISO-8601 UTC",
  "images": {
    "<sop_uid>": {
      "state": "done | skipped",
      "side": "L",
      "y_pos": 1,
      "points": {
        "H":  {"x": 123.5, "y": 88.0, "state": "visible", "confidence": 3},
        "B1": {"x": 130.0, "y": 96.5, "state": "visible", "confidence": 3},
        "T":  {"state": "not_visible", "confidence": 2}
      },
      "comment": "", "seconds": 54.3, "updated": "ISO-8601 UTC"
    }
  }
}
```

Координаты — **в пикселях исходного DICOM**, с честным пересчётом из экранных
(масштаб под окно, зум, панорамирование), как в `foreign_annotator.py`.
Размеры проверяются по фактическому массиву пикселей против `rows`/`cols`.

## Интерфейс

- Снимок крупно, справа — список шести точек с состояниями, прогресс, таймер.
- Текущая точка подсвечена; клик ставит её и автоматически переходит к следующей.
- Клавиши: `1`…`6` — выбрать точку, `V`/`X`/`O`/`?` — состояния visible / not_visible /
  out_of_frame / uncertain для текущей точки, `1`…`3` на цифровой клавиатуре или
  `Shift+1..3` — уверенность, `N`/`P` — следующий/предыдущий снимок, `D` — удалить
  текущую точку, `S` — пропустить снимок.
- Яркость/контраст, зум, панорамирование — как в `foreign_annotator.py`.
- **Направляющие уровней D и D₂**: после постановки T (или B₁B₂, если T не виден)
  на снимке рисуются две горизонтальные линии на 2 см и 5 см ниже — разметчик ставит
  D и D₂ на них. Линии рисуются в экранных координатах, но считаются в миллиметрах.
- Сторона (`L`/`R`) показывается крупно: от неё зависит, какое направление медиальное.

## Режим проверки повторяемости

`python tools/hip_annotator.py --report data/annotations/hip_points_<annotator>.json`
печатает, ничего не открывая:

- сколько снимков размечено, сколько пропущено;
- по каждой точке: доля `visible` / `not_visible` / `out_of_frame` / `uncertain`,
  **отдельно для положительных и отрицательных по `y_pos`** (доля невидимого T по
  классам — потенциально самостоятельный признак);
- по скрытым повторам: разброс координат каждой точки в миллиметрах (SD и максимум),
  сравнение с порогами 1,5 мм и 3 мм, вывод «проходит / не проходит»;
- предупреждение, если порог не пройден: разметку стоит остановить и уточнить правила.

## Чего делать не надо

- Не менять существующие инструменты.
- Не хранить в JSON путей к файлам и идентификаторов пациента — только `sop_uid`.
- Не считать сами признаки ротации (f₁ и прочие) — это отдельный модуль, не твоя задача.
