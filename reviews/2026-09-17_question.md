# Вопрос внешним моделям (2026-09-17)

Ты опытный ML-инженер в медицинской визуализации и рецензент. Нужен критический разбор плана соревновательного проекта. Отвечай по-русски, по пунктам, конкретно. Указывай, где рассуждение ошибочно или рискованно, что поменять в последовательности и что бы ты сделал иначе. Не пересказывай вводные.

## Задача (ТЗ соревнования, Москва, ДЗМ)
ИИ-сервис контроля качества DXA-денситометрии. Вход: DICOM-исследования (до 3 изображений), поясничный отдел позвоночника и проксимальный отдел бедра. Выход (csv/xlsx, строка на изображение): anatomical_region («Поясничный отдел позвоночника» / «Проксимальный отдел бедра»), quality_class 0/1, quality_prob [0;1], violation_type — закрытые списки через «;»:
- поясница: «Некорректная укладка» (в кадре должны быть верхние края подвздошных костей внизу и половина тела Th12 вверху); «Не выравнена ось позвоночника» (наклон > 5°); «Присутствуют посторонние предметы»;
- бедро: «Некорректная укладка» (видны большой вертел, шейка, седалищная кость; ротация — малый вертел едва виден: не виден = переротация, большой = недоротация); «Некорректная область интереса» (поля ≥3 см сверху/снизу, ≥2 см сбоку).
Оценка: F1 и ROC-AUC (приоритет), Se/Sp, macro-F1 по типам, 95% ДИ; ≤3 мин на исследование; Docker, без интернета, воспроизводимость; закрытый тест у организатора. Жюри смотрит на дисбаланс и утечку данных.

## Данные организатора (проверено)
- Один аппарат GE Lunar Prodigy Advance, DICOM CR, MONOCHROME2 8 бит, маленькие снимки ~180–405 × 248/280/300 px. Разметки аппарата/текста на снимках нет. PixelSpacing нет. PatientID анонимизирован.
- 100 исследований, 499 файлов, но уникальных по пикселям изображений 252 (копии идентичны байт в байт, отличаются только поля экспорта: ExposedArea, число экспозиций, SOP UID).
- Размечено 249 изображений: поясница 99 (брак 32: укладка 6, ось 10, предметы 17), бедро 150 (брак 41: укладка 36, область интереса 7). Разметка по исследованию: колонки правое/левое бедро. 3 противоречивые строки (итог=1 без отмеченных нарушений при сколиозе; ось=1 при итоге=0 при переломе). Сколиоз в 11 других — норма. 3 бедра с эндопротезами не размечены.
- Посторонние предметы глазами — чаще всего косточки бюстгальтера вверху кадра; «область интереса» бедра — узкие обрезанные кадры (180–261 строк).

## Наши умозаключения
1. Область: Columns==300 → поясница, иначе бедро — 100% совпадение с разметкой. Сторона бедра (нужна только чтобы связать с меткой правого/левого): центр масс яркости верхней трети относительно нижней — 100% совпадение, запас большой.
2. Размер пикселя: организатор написал 1,05 мм (Y) × 0,6 мм (X). Мы считаем, что выгруженные картинки уже квадратные ~0,6×0,6: ExposedArea/размер у поясниц = 0,600×0,606; автозамер 99 поясниц — период «тело+диск» 51 px, ширина тела 69 px (при 0,6 мм это 31 и 41 мм — анатомически норма; при 1,05 по Y сегмент 54 мм — нереально); диафиз бедра 43 px = 26 мм при 0,6. Рабочее значение 0,6 (3 см ≈ 50 px, 2 см ≈ 33 px), параметр в конфиге.
3. Разбиение только по исследованиям, дубли схлопнуть; StratifiedGroupKFold 5 фолдов + holdout 15–20%; пороги по OOF; ДИ кластерным бутстрэпом по исследованиям.

## План (последовательность)
1. Метрики + разбиение; бейзлайн «норма/нарушение» — маленькая предобученная CNN на область, БЕЗ внешних данных (это MVP для промежуточной сдачи; там же нужна «оценка корректности разметки хотя бы одной области» — наклон оси поясницы).
2. Классическая геометрия без обучения: центр столба по строкам → прямая L1–L4 → угол; гребни подвздошных костей — яркие области внизу; маска бедра порогом → поля до краёв в мм; выступ малого вертела на медиальном контуре. Проверить, разделяют ли признаки метки.
3. Модели нарушений независимы: предметы — CNN по всему снимку (+ классика по ярким компактным объектам); ось/укладка поясницы — геометрия (+CNN); укладка бедра — CNN на кроп малого вертела + геометрия; область интереса — поля в мм + простой классификатор.
4. quality_prob — не нейросеть: 1−Π(1−p_k) или логистическая регрессия по OOF-вероятностям подмоделей.
5. Сервис: FastAPI + CLI, Docker, тесты на битых файлах.

## Внешние данные (скачаны)
- kaggle «dexa-osteo»: ~174 настоящих DXA поясницы GE Lunar, кадр обрезан по ROI, на снимке нарисована жёлтая разметка L1–L4 и контуры тел; классы остеопороза; лицензия не указана. План: выделить жёлтые линии по цвету → маски/границы позвонков как бесплатные метки → стереть линии inpainting → обучать модель позвонков.
- TotalSegmentator v2: 1228 КТ с масками позвонков, таза, бёдер (CC BY). План: DiffDRR, параллельная AP-проекция «костной» плотности, 0,6 мм, 8 бит; синтез нарушений параметрами (поворот в корональной плоскости 0–12° → ось; сдвиг окна → Th12/гребни вне кадра; ротация бедра вокруг длинной оси → малый вертел; сужение поля → область интереса; вставка металлических объектов). Критерий «идём/не идём»: модель только на синтетике должна дать сигнал на реальных данных, иначе по этому нарушению синтез бросаем.
- AASCE 2019 (609 AP-рентгенограмм позвоночника, 68 точек), VertebraeKeypoints50 — предобучение точек позвонков.
- object-CXR (10 000 рентгенограмм грудной клетки, половина с посторонними предметами) — предобучение детектора предметов.
- Эндопротезы бедра (2 набора), FracAtlas — только проверка устойчивости.
- Отбраковали: большой «chinese osteoporosis dxa» на Kaggle (оказались обычные рентгенограммы и имена пациентов в именах файлов), копию VinDr-SpineXR на Kaggle в обход DUA.
- Внешние/синтетические — только в обучающие фолды, метрики только на данных организатора, абляции «с/без» с ДИ. Ручная разметка в CVAT — только того, что не закроется.
- Вычисления: V100 на кластере (сессии 4 ч), локально CPU.
