# Консультация gpt-astra: размер пикселя, целевая метка, метрики (2026-09-17)

### 1. Размер пикселя
**Решение:** По умолчанию для **выгруженного растра** фиксируем `sx=0,600`, `sy=0,606 мм/px`: это лучше всего поддержано приведёнными данными. Альтернативу `0,600 × 1,050` считаем отдельным анализом чувствительности; выбор масштаба фиксируем **до оценки F1**, не переключаем по метрикам. Организатору отправляем пример с 289 строками и просим подтвердить масштаб именно экспорта.

**Риск/оговорка:** Ресэмплинг — правдоподобная гипотеза, не доказанный факт; ExposedArea не заменяет PixelSpacing. Перенос масштаба на бедро пока менее подтверждён; прямое указание организатора создаёт риск несовпадения с оцениванием.

### 2. `quality_class` и спорные метки
**Решение:** Согласен: целевая метка — **OR отдельных критериев**, «Итог» игнорируем: №6/11 → 0, №35 → 1. Маски из-за этих расхождений снимаем; «ось» №6/11 оставляем отрицательной, не маскируем. `quality_class` — OR пороговых решений по применимым критериям; `quality_prob` — оценка вероятности их объединения.

**Риск/оговорка:** Сколиоз, перелом и эндопротез сами по себе не нарушения, но не отменяют положительную критериальную метку. `max(p_i)` — допустимый скор, не автоматически вероятность объединения; `1−∏(1−p_i)` требует допущения независимости. Отдельный порог `quality_prob` не должен подменять заявленный OR.

### 3. Метрики
**Решение:** Согласен с основным набором: бинарные F1 и ROC-AUC по всем изображениям, отдельно — по областям; положительный класс — «есть нарушение». Затем пять критериальных F1 и **macro-F1 как их простое среднее**; каждый критерий оцениваем только на применимой области. Вариант с четырьмя классами не нужен как основной — максимум внутренний диагностический отчёт.

**Риск/оговорка:** Организатор явно подтвердил пять типов, но не точную бинарную метрику и порядок ранжирования — это стоит уточнить. Пороги подбираем только на обучении/валидации без пересечения пациентов; правило для классов без положительных примеров фиксируем заранее.
