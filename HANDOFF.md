## 4. Веса — НЕ в git

`*.pt` и `models/` в `.gitignore`. Файлы лежат локально у владельца проекта
(`~/projects/dxa-quality-ai/models/`) и на кластере Aldan (`~/dxa/models/`),
передаются отдельно.

| файл | размер | назначение |
|---|---|---|
| `quality_cnn.pt` | 45 МБ | CNN: область снимка, бедро, запасные головы |
| `spine_keypoints.pt` | 57 МБ | точки позвоночника → обрезка и ось |
| `foreign_patch.pt` | 2,8 МБ | **предметы**: ансамбль 5 моделей с предобучением, порог 0,978 |
| `foreign_patch_scratch.pt` | 2,8 МБ | прежний вариант без предобучения (для отката) |
| `ocxr_pretrain.pt` | 0,6 МБ | предобученные веса (для воспроизведения) |

Без `quality_cnn.pt` сервис не оценивает бедро вообще; без `foreign_patch.pt` —
откатывается на старую CNN-голову предметов.

## 5. Как запустить

```bash
PYTHONPATH=src python -m dxaqc.cli predict --input <папка или zip с DICOM> \
    --output result.csv --models models --device cuda   # или cpu
```

Проверено на `data/test` (3 снимка организатора): ошибок 0, решения CPU и GPU
совпадают. Время: GPU — 1,1 с на снимок поясницы, всего 10 с на 3 снимка;
CPU — 6,6 с на поясницу, 82 с на 3 снимка (в основном загрузка моделей).

## 7. Ограничения, которые надо честно назвать в отчёте

- Все находки получены на тех же 99 + 153 снимках, где считается метрика: анализ
  поисковый, конвейер зафиксирован, но выбор конвейера информирован этими данными.
- Замена модели предметов — отклонение от заранее зафиксированной маршрутизации
  (оформлено в `docs/final_protocol.md`).
- Положительных примеров мало (6–36 на нарушение): F1 заметно зависит от порога,
  AUC устойчивее. Для предметов F1 между прогонами 0,6–0,83.
- Внешний набор object-CXR использован только для предобучения; вся оценка —
  на снимках организатора.
