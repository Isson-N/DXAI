## Разъяснения организатора (docx)

- **Размер пикселя:** 1,05 мм по Y и 0,6 мм по X, аппарат во всех наборах один. По данным выгруженные
  картинки квадратные ~0,6 мм — см. раздел «Размер пикселя» ниже.
- **`violation_type`** — закрытые списки, несколько значений через `;`, если нарушений нет — пусто:
  - поясница: «Некорректная укладка»; «Не выравнена ось позвоночника»; «Присутствуют посторонние предметы»
  - бедро: «Некорректная укладка»; «Некорректная область интереса»
- **`quality_prob`** — можно добавить колонку с вероятностью нарушения в диапазоне [0; 1] (для ROC-AUC).
- **`anatomical_region`:** «Поясничный отдел позвоночника» или «Проксимальный отдел бедра».
  Сторона не нужна. В закрытом тесте суффиксов (`_ПОП`, `_ППОБ`, `_ЛПОБ`) в именах файлов не будет.

## DICOM: что внутри

- **Объект:** Computed Radiography Image Storage (`Modality = CR`), а не Secondary Capture. Один аппарат —
  GE Healthcare **Lunar Prodigy Advance**, ПО 18.41.005 (399 файлов) и 18.50.082 (100 файлов).
- **Картинка:** `MONOCHROME2`, 8 бит, маленькая — 180–405 строк × 248/280/300 столбцов.
  Это «чистый» снимок кости, фон и мягкие ткани частично замаскированы чёрным (ступенчатые края).
  **Разметки аппарата (ROI, линии позвонков), текста, оверлеев нет.**
- **Нет:** `PixelSpacing`, `ImagerPixelSpacing`, `BodyPartExamined`, `Laterality`, `ImageLaterality`,
  приватных тегов. `SeriesDescription` у всех «Изображения DXA» / «DXA Images» — область по тегам не узнать.
- **Есть:** `ExposedArea` (например, `[180, 175]`), `TotalNumberOfExposures`, `ExposureDoseSequence` (76 кВ),
  `PatientOrientation = [L, F]` у 379 файлов.
- **Анонимизация:** `PatientID`, даты, возраст, пол — строка `Anonymized` → **группировать по пациенту
  нельзя**, только по исследованию. `StudyInstanceUID` в тегах **не совпадает** с именем папки,
  а разметка ссылается на **имя папки**.
- Предупреждения pydicom: `LO` длиннее 64 символов, UID из цифр с ведущими нулями — файлы читаются,
  но ридер должен это переживать.

### Дубли — проверено, настоящие
499 файлов, но уникальных по пикселям изображений **252**: 127 изображений лежат в исследовании
в 2–10 копиях с разными `SOPInstanceUID`. Проверка (16.09.2026):
- внутри каждой группы копий пиксели совпадают **байт в байт**, размеры одинаковые;
- отличаются только служебные поля экспорта: `InstanceNumber`, `SOPInstanceUID`, `ExposedArea`,
  `TotalNumberOfExposures`, `EntranceDoseInmGy`, `ExposureDoseSequence`, иногда `PatientOrientation`,
  `ProtocolName`, `SeriesInstanceUID`. Типичная пара: копия с `ExposedArea = [180, 174]` и 2 экспозициями
  (выгрузка одной области) и копия с `[520, 526]` и 6 экспозициями (выгрузка всего исследования);
- почти-копий нет: среди разных изображений максимальная корреляция уменьшенных (32×32) картинок —
  0,968, и это разные бёдра разных людей (просто похожая форма). Повторных исследований одного
  пациента по картинкам не видно.

Для обучения и метрик использовать только уникальные (`index/images.csv`). Вопрос организатору
остаётся один: в ответе нужна строка на каждый файл или на уникальное изображение.

### Как определить область и сторону (правила в `tools/build_index.py`)
- **Область:** `Columns == 300` → поясница, иначе (280 или 248) → бедро. Совпало с разметкой во всех 100 исследованиях.
- **Сторона бедра:** центр масс яркости верхней трети снимка по отношению к нижней трети.
  Головка и таз медиальнее диафиза: у правого бедра они справа на снимке, у левого — слева.
  Сверено с тестовыми `*_ППОБ` и `*_ЛПОБ`, совпало с разметкой во всех исследованиях, запас большой
  (|сдвиг| ≥ 40 пикселей). Стороны в ответе не нужны, но нужны, чтобы связать изображение с меткой
  («правое» или «левое» бедро в `разметка.xlsx`).
- ⚠ В закрытом тесте размеры могут отличаться — это правило для разбора, а не для сервиса.

## Разметка (`train/разметка.xlsx`)

Один лист «Калибровка», шапка в две строки (объединённые ячейки), строки — исследования по имени папки:

| Колонки | Смысл |
|---|---|
| Позвоночник: корректная укладка / ось (до 5°) / посторонние предметы | 1 = нарушение |
| Правое бедро: позиционирование-ротация / корректность области интересов | 1 = нарушение |
| Левое бедро: то же | |
| Итог: позвоночник / правое / левое | 1 = есть нарушение; пусто = области нет в исследовании |
| Комментарий | «сколиоз» (13), «перелом», «L6, люмбализация», «эндопротезирования ТБС» и др. |

Справа на листе — счётчики `COUNTIF` с устаревшими диапазонами, их не использовать.

Соответствие колонок ответу: «укладка» (позвоночник) и «позиционирование/ротация» (бедро) →
«Некорректная укладка»; «ось» → «Не выравнена ось позвоночника»; «посторонние предметы» →
«Присутствуют посторонние предметы»; «область интересов» → «Некорректная область интереса».

## Размер пикселя: 0,6 × 0,6 мм (вывод по данным, 16.09.2026)
Организатор написал 1,05 мм по Y и 0,6 мм по X. На выгруженных картинках пиксель **квадратный, ~0,6 мм**.
Три независимых признака:
1. **`ExposedArea`** у копий, выгруженных по одной области: для 89 снимков поясницы
   `ExposedArea / размер в пикселях` = **0,600 (X) и 0,606 (Y)**, для бедра по X тоже ~0,607.
2. **Пропорции позвонков** (не зависят от абсолютного масштаба), автоматический замер на всех 99 поясницах:
   период «тело + диск» по вертикали — медиана **51 пиксель**, ширина тела — медиана **69 пикселей**,
   отношение ширина / период — медиана **1,33**.
   - при квадратном пикселе 0,6 мм: сегмент 31 мм, ширина 41 мм, отношение 1,3 — анатомически нормально
     (у взрослого сегмент 30–40 мм, ширина тела 40–50 мм);
   - при 1,05 × 0,6 мм: сегмент 54 мм (так не бывает), ожидаемое отношение ~2,2 вместо 1,33.
3. **Бедро:** диафиз на тестовом `CR000000_ППОБ` ~43 пикселя = 26 мм при 0,6 мм (норма), 45 мм при 1,05.

Вероятно, 1,05 × 0,6 мм — шаг исходного сканирования аппарата, а при выгрузке изображение пересчитано
на квадратный пиксель. **Рабочее значение: 0,6 × 0,6 мм** (в конфиге, чтобы легко поменять).
Для критериев бедра: 3 см ≈ 50 пикселей, 2 см ≈ 33 пикселя. Подтвердить на разметке «Некорректная
область интереса», когда будут признаки полей.

## Что видно глазами (`overview/`)
- **Посторонние предметы (поясница):** чаще всего дуги косточек бюстгальтера вверху кадра, также
  клипсы, проволока, мелкие металлические точки.
- **Некорректная укладка (поясница):** в кадр не попадают гребни подвздошных костей или кадр смещён.
- **Ось:** видимый наклон столба; часто вместе со сколиозом.
- **Некорректная область интереса (бедро):** узкие, обрезанные кадры (180–261 строк), мало поля
  вокруг вертела и диафиза.
- **Некорректная укладка (бедро):** ротация (малый вертел большой или не виден), кадр смещён в сторону таза,
  широкие кадры с тазом.
- **Особые случаи:** эндопротезы (яркий металл, ширина 248), переломы, L6 (люмбализация).
- Форма чёрной маски по краям снимка может коррелировать с классом — модель должна смотреть на кость,
  а не на маску (проверять Grad-CAM).
