## 0. Суть

Сервис по DICOM выдаёт на изображение: область, `quality_class`, `quality_prob`, нарушения из закрытых списков.
- **Ядро — лучший простой бейзлайн** (этап 3), выбранный по честной валидации.
- **Ключевые точки** — там, где нужны измерения: обязательная для MVP оценка поясницы (угол оси, видимость Th12
  и гребней) и объяснения на снимке. Объединение точек с бейзлайном — один условный эксперимент.
- Внешние данные, синтез из КТ, доп. функционал — вне основного пути (раздел 5).

Почему так: 252 уникальных изображения, 73 с нарушением, редкие классы 6 и 7, команда 1–2 человека.

## 1. Исходные факты и допущения

- Один аппарат GE Lunar Prodigy Advance, CR, 8 бит, ~180–405 × 248/280/300 px; разметки и текста на снимках нет.
- 499 файлов → 252 уникальных изображения (копии идентичны по пикселям); размечено 249: поясница 99
  (брак 31 по OR критериев: укладка 6, ось 10, предметы 17), бедро 150 (брак 41: укладка 36, область интереса 7).
- Спорные метки: №6, №11 (итог = 1 без отмеченной причины), №35 (ось = 1, итог = 0). Не размечены 3 изображения
  бедра с эндопротезами из 2 исследований (№66 правое, №70 оба).
- `PatientID`, даты, возраст, пол — строка «Anonymized»; одинаковых или почти одинаковых снимков между исследованиями
  нет. **Допущение:** исследования независимы; группы = исследования.
- `PixelSpacing` нет. Организатор: 1,05 (Y) × 0,6 (X) мм; косвенные данные согласуются с ~0,6 × 0,6.
  **Не подтверждено** → миллиметры только условные, в двух сценариях.
- «Columns == 300 → поясница» и сторона бедра по центру масс совпали с разметкой на 100%, но найдены на тех же
  данных → используются только для связи изображений с метками и как проверка в логах.

## 2. Валидация

1. **Разбиение:** один фиксированный `StratifiedGroupKFold` по исследованиям, 5 фолдов; дубли схлопнуты.
   Фолды — в git (`experiments/folds.csv`).
2. **Выполнимость:** до экспериментов проверить, что во **внутренних обучающих частях** есть оба класса каждого
   применимого нарушения. Где их нет — для этой головы заранее заданное правило вместо подбора
   (порог правила ТЗ по признаку или порог 0,5 без подбора).
3. **Вложенность всего конвейера:** внешний тестовый фолд не участвует в обучении ни одного компонента
   (энкодер, модель точек, признаки, калибровка, пороги, объединение, выбор вариантов и аугментаций).
   При внутреннем кросс-фиттинге исключённый фолд не участвует и в обучении точек и энкодера.
   Решения, принятые по внешним OOF, — итог помечается «оценка разработки».
4. **Метрики** (п. 8.4 ТЗ; все считаются из одних и тех же прогнозов): по области и в целом — F1 и ROC-AUC (приоритет),
   Se, Sp, balanced accuracy, PR-AUC (AP); по нарушениям — F1, Se, ROC-AUC, число положительных; macro-F1 по нарушениям.
   **F1 и Se/Sp — по реально выдаваемому `quality_class`, AUC — по `quality_prob`.**
5. **95% ДИ:** кластерный бутстрэп по исследованиям; реплики без положительных или без отрицательных для AUC/AP
   пропускаются, их доля указывается.
6. **Метки** — критерии организатора; «есть нарушение» = OR критериев (обновление 17.09, п. 3). Основная оценка на всех 249,
   масок нет; решение по №6, 11, 35 зафиксировано в `experiments/label_policy.csv`. Эндопротезы без меток в метриках не участвуют.
7. **Внешние и преобразованные данные** — только во внутренних обучающих частях.

### Этап 1. Каркас сервиса и протокол (неделя 1)
> **Статус 17.09.2026: сделано**, кроме отправки вопросов (текст готов: `docs/questions_to_organizer.md`). Подробности — `NOTES.md`.
- CLI: папка/архив → чтение DICOM (битые файлы → `Failure`, обработка продолжается) → заглушка → csv/xlsx

- Dockerfile с фиксированными версиями; smoke-тест с `--network none` на `data/test`.
- `dxaqc/metrics.py`, `experiments/folds.csv`, проверка выполнимости (2.2), `experiments/label_policy.csv`.
- **Отправить вопросы организатору** (раздел 6).
- Переход: контейнер выдаёт валидный файл; фолды и политика меток зафиксированы.

### Этап 2. Разметка поясницы — пилот (неделя 1–2, человек)
- CVAT, пилот на 15–20 снимках → реальная трудоёмкость → остальные 99 поясниц.
- Размечаем только то, что используется в MVP:

| Критерий ТЗ | Измерение | Разметка | Когда «неизмеримо» |
|---|---|---|---|
| Вверху видна половина тела Th12 | верхний край кадра выше середины тела Th12 | середины верхней и нижней пластинок Th12 **+ метка «видно ≥ половины / < половины / невозможно определить»** (цель головы видимости) | пластинка вне кадра → решает голова видимости; «невозможно определить» маскируется в обучении и выдаётся как «неизмеримо», не как норма |
| Внизу видны верхние края подвздошных костей | верхняя точка гребня в кадре | верхняя точка гребня слева и справа + флаг «в кадре / частично / вне» | «частично» — отдельное состояние |
| Наклон оси ≤ 5° | угол прямой через центры тел позвонков от верхнего до нижнего видимого (организатор) к вертикали кадра: `atan2(|Δx|·sx, |Δy|·sy)`, sx = 0,600, sy = 0,606 | середины верхней и нижней пластинок каждого видимого позвонка Th12–L5 (центр — середина между ними) | видно < 3 позвонков |

- 20 снимков повторно (повторяемость разметки).
- Если разметчика нет: этап 4 выполняется без измерений поясницы, требование MVP о разметке отмечается как невыполненное
  (или ждёт разметки — решает команда).

### Этап 3. Бейзлайны (неделя 2)
- **B0** (внутри каждой области): логистическая регрессия по размеру кадра и тегам экспорта — показывает вклад размера.
- **B1:** замороженный предобученный энкодер + регуляризованные линейные головы.
- **B2:** небольшая CNN (ResNet18/EfficientNet-B0) с общим энкодером, головы: область, «есть нарушение», нарушения
  (маскирование неприменимых голов).
- Вход: без искажения пропорций, паддинг; левые бёдра зеркалятся в правые (сторона по правилу, один раз сверена
  вручную по `data/overview/`). Аугментации только фотометрические; без поворотов, обрезки, отражений поясницы.
- Область в сервисе — голова B2; правило по размеру — предупреждение при расхождении.
- Выбор B1/B2 — внутри внешних обучающих частей (2.3).

### Этап 4. MVP к промежуточной сдаче (неделя 3)
- Модель точек поясницы (тепловые карты, небольшая U-Net) + голова видимости Th12/гребней.
- Измерения: угол L1–L4, положение середины Th12 и гребней относительно краёв — **в пикселях и условно в мм в двух
  сценариях** (sx = sy = 0,6; sx = 0,6, sy = 1,05). Расхождение сценариев запрещает только геометрическое жёсткое
  правило, **официальные метки не маскируются**.
- Выход: лучший бейзлайн + измерения поясницы как объяснение; «корректность разметки области» = проверка укладки
  поясницы по снимку — **подтвердить у организатора** (вопрос 8).
- Сервис с моделью; метрики с ДИ; ограничения и план.

### Этап 5. `quality_class`, `quality_prob`, пороги (неделя 4)
- `quality_prob` — оценка вероятности «изображение имеет нарушение качества» (официальный итог = 1):
  прямая голова «есть нарушение» (выбор калибровки — внутри 2.3).
- `quality_class` = 1, если хотя бы одно нарушение прошло порог (OR, как у организатора); `violation_type` — прошедшие
  порог через «;», пусто при норме. `quality_prob` — оценка вероятности «хотя бы одно нарушение», по ней организатор
  считает ROC-AUC; расхождение с `quality_class` измеряется и описывается.
- Пороги — внутри внешних обучающих частей.

### Этап 6. Сервис по ТЗ (недели 4–6)
- CLI + **API пакетной обработки (обязателен, п. 3.2 ТЗ)**, Docker без сети, фиксированные версии и сиды,
  замер времени (≤ 3 мин на исследование) и ресурсов, тесты на битых и нестандартных DICOM.
- Кеш прогнозов для копий: хеш пикселей + форма + теги интерпретации + версия модели.
- README и руководства (п. 5 ТЗ).
- **Подготовка к публикации репозитория** (сдача — ссылка на публичный репозиторий): убрать внутренние сведения
  (пути и логин кластера, журнал), проверить отсутствие данных организатора и идентификаторов; ссылку прикрепить
  на платформе заранее, не в последний день.

### Этап 7. Финал (недели 6–8)
- Обучение финальных моделей на всех данных по зафиксированному протоколу; прогон контейнера на чистой машине.
- Презентация: аудит данных, протокол валидации, метрики с ДИ, анализ ошибок, объяснения, ограничения
  (масштаб пикселя, один аппарат, редкие классы, допущение независимости исследований).
