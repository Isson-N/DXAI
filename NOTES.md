# dxa-quality-ai — журнал

Соревнование ДЗМ (ДепЗдрав): ИИ-сервис оценки качества DXA-исследований (денситометрия).
ТЗ: `data/4. ДепЗдрав.pdf` (12 стр.). Все входные файлы и описание данных — в `data/` (см. `data/README.md`).

## Суть ТЗ (ключевые числа)
- Вход: DICOM без разметки, в исследовании ≤3 изображений/серий. Области: поясница, проксимальный отдел бедра.
- Поясница: в скане гребни подвздошных костей (низ) и половина Th12 (верх); наклон оси ≤5° (пример: 1,6° норма, 6,9° брак); посторонние предметы/металл (косточки белья).
- Бедро: видны большой вертел, шейка, седалищная кость; ротация по малому вертелу (переротирована — контур гладкий, недоротирована — вертел большой); поля от ROI ≥3 см сверху/снизу, ≥2 см сбоку.
- Выход: csv/xlsx, строка = изображение: path_to_study, study_uid, image_uid, anatomical_region, quality_class (0/1), violation_type, processing_status, time_of_processing.
- Опционально: доп. серия с маской/точками/heatmap, DICOM SR, автокоррекция разметки, веб-интерфейс.
- ≤3 мин на исследование; контейнер, скрипт сборки, API пакетной обработки, фиксированные версии, без внешних сервисов.
- Финальный тест: 2×H200 141GB (44 CPU, 256 RAM) на закрытых данных, метрики считает организатор.
- Метрики: Se, Sp, balanced acc, F1, ROC/PR AUC, macro-F1 по типам; приоритет F1 и ROC-AUC, с 95% ДИ; по областям и типам нарушений.
- Жюри отдельно смотрит на дисбаланс классов и утечку train/test.
- Промежуточная сдача (MVP): бинарный класс + корректность разметки хотя бы по одной области + метрики на валидации.
- Данные: получены 16.09.2026, лежат в `data/` (zip + распакованные `train/`, `test/`).

  (вопрос: reviews/2026-09-20_next_steps_question.md). Ключевое:
  1) Порядок по отдаче на час: рамки предметов + локальная модель → геометрия бедра (сначала oracle по
     ручным точкам!) → аудит «оси» → пороги → внешние данные. Честный прогон качество не повышает,
     но повышает достоверность.
  2) Нельзя называть маршрутизацию «априорной»: она выбрана после разведки на той же выборке.
     Правильно — «зафиксировано после разведки, до финального расчёта». Новый split старых снимков
     независимого теста НЕ создаёт. → docs/final_protocol.md переписан.
  3) Схема бедра из 5 точек недостаточна: «ось шейки» и «ось диафиза» — направления, нужны 2 точки
     диафиза (D, D2) и 2 края шейки (B1,B2); T — НАИБОЛЕЕ МЕДИАЛЬНО ВЫСТУПАЮЩАЯ точка малого вертела,
     а не его центр. Первый признак: f1 = ((T−D)·n)/w, n — нормаль к оси диафиза, w — ширина шейки.
     go/no-go: oracle AUC ≥ 0,75 и ΔF1 ≥ 0,10 против CNN, иначе сеть точек на бедре не обучать.
     Точки — не с нуля: энкодер поясничной сети, 5–10 эпох заморожен, потом последний блок с lr/5–10.
  4) Предметы: первый выбор — патч-классификатор по рамкам + hard-negative mining (верхние яркие линии,
     края костей, подписи), NMS, оценка по локализации (FROC), а не по максимуму вероятности кадра.
     Победа над shortcut проверяется тремя тестами, включая контрфактический (дорисовать/убрать верхнюю
     линию + контрольная манипуляция той же площади). Цель на кадре: 14 TP при FP ≤ 3 (F1 0,824 vs 0,75).
  5) Арифметика: 12/3/5 = precision 0,80, recall 0,706, F1 0,75 (в текстах не путать precision с accuracy).
  6) Порог полезности любого эксперимента задан заранее: Δmacro-F1 ≥ 0,02 (= ΔF1 ≥ 0,10 одной головы).
  7) Метку «ось» из основной macro-F1 НЕ исключать; отчёт тремя блоками, 0,48 называть «лучший F1
     исследованного семейства угловых правил», а не потолком задачи.
  8) Недооценено мной: разбор 7 положительных по ROI бедра (один TP заметно двигает F1) и механизм
     отказа геометрии при ошибке головы присутствия.
