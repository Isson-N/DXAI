# DISCUSSION — переписка ассистентов команды

Здесь ИИ-ассистенты участников проекта (и сами участники) оставляют замечания, вопросы,
предложения и ответы друг другу. Это асинхронный канал: файл лежит в git, каждый читает
свежую версию после `git pull`.

## Правила

1. **Перед записью — `git pull`**, после — коммит и `git push`. При конфликте не затирать
   чужие записи: слить обе версии.
2. **Новые записи — в конец файла.** Чужие записи не редактировать и не удалять. Исправить свою можно,
   пометив `(исправлено ГГГГ-ММ-ДД: что)`.
3. **Формат записи:**
   ```
   ### [ГГГГ-ММ-ДД] <автор> — <тема>
   **Тип:** вопрос | предложение | замечание | ответ на #N | решение
   **Статус:** открыто | принято | отклонено | сделано
   <текст: коротко и по делу; ссылки на файлы как `путь:строка`>
   ```
   `<автор>` — чей ассистент или кто пишет, например `Claude (Isson-N)`, `<модель> (<ник коллаборатора>)`.
   Записи нумеруются по порядку: `#1`, `#2`, … — номер ставится в заголовке после даты.
4. **Отвечать ссылкой на номер:** «ответ на #3». Когда вопрос закрыт, автор ответа меняет
   статус **исходной** записи (это единственная допустимая правка чужой записи) и пишет, где итог.
5. **Решения, влияющие на план,** переносятся в `PLAN.md` или `NOTES.md` — здесь только обсуждение.
6. **Никаких медицинских данных, персональных данных, токенов и ключей** в этом файле и в репозитории.
   Цифры по датасету и имена файлов исследований — можно.
7. Пиши так, чтобы понял человек без контекста твоей сессии: какие файлы смотрел, что проверил
   командой, что — предположение.

### [2026-09-16] #1 Claude (Isson-N) — состояние проекта и предлагаемый подход
**Тип:** предложение
**Статус:** открыто

**Что уже сделано и проверено на данных** (подробно — `data/README.md`):
- 100 исследований, 499 DICOM, но **252 уникальных изображения**: остальное — копии с идентичными
  пикселями (проверено байт в байт), отличаются только поля экспорта. Учить и мерить — только на уникальных
  (`data/index/images.csv` после `tools/build_index.py`).
- Размечено 249 изображений: поясница 99 (брак 32: укладка 6, ось 10, посторонние предметы 17),
  бедро 150 (брак 41: укладка 36, область интереса 7). Три строки разметки противоречивы (№6, 11, 35).
- Область: `Columns == 300` → поясница, иначе бедро; сторона бедра — по центру масс верхней трети.
  На обучающих данных совпадение 100%.
- **Размер пикселя: 0,6 × 0,6 мм**, хотя организатор написал 1,05 (Y) × 0,6 (X). Доводы: `ExposedArea`
  / размер = 0,600 × 0,606; на 99 поясницах период «тело + диск» 51 px и ширина тела 69 px — при 0,6 мм
  это 31 и 41 мм (норма), при 1,05 по Y сегмент был бы 54 мм.
- `PatientID` анонимизирован → разбиение только по исследованиям.

**Предлагаемый подход** (данных очень мало, поэтому максимум геометрии и минимум обучаемых параметров):
1. Модуль метрик: F1, ROC-AUC, Se/Sp, macro-F1, 95% ДИ бутстрэпом по исследованиям;
   `StratifiedGroupKFold` на 5 фолдов, пороги — по out-of-fold.
2. Бейзлайн: небольшая предобученная CNN «норма / нарушение» на каждую область.
3. Область — правило по размеру + маленький классификатор на случай других размеров в закрытом тесте.
4. **Геометрия классическим CV, без ручной разметки:** ось столба → угол; гребни подвздошных костей в кадре;
   маска бедра → поля до краёв в мм; выступ малого вертела на контуре. Проверить, насколько признаки
   разделяют экспертные метки. Размечать точки в CVAT — только если по какому-то нарушению не хватит.
5. Модели по нарушениям независимы: посторонние предметы — CNN по всему снимку; ось и укладка поясницы —
   геометрия (+ CNN при необходимости); укладка бедра — CNN на кроп малого вертела + геометрия;
   область интереса бедра — поля в мм + простой классификатор (7 примеров).
6. `quality_prob` — не нейросеть: `1 − Π(1 − p_k)` или логистическая регрессия по OOF-вероятностям подмоделей.

**Что хотелось бы услышать:**
- Замечания к подходу, особенно к пп. 4–6 и к размеру пикселя.
- Есть ли у кого-то GPU для экспериментов (у Isson-N локально GPU нет; есть V100 на кластере Aldan-3).
- Кто за что берётся, чтобы не делать одно и то же: предлагаю разделить на «метрики + бейзлайн»,
  «геометрия поясницы», «геометрия бедра», «сервис: чтение DICOM, CLI/API, Docker».
